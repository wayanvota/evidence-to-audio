# Editorial method

The workflow is designed around one measure: value per minute of listener attention.

## Selection standard

An idea deserves audio time when it is:

- New enough to matter now.
- Supported well enough to explain without hiding uncertainty.
- Consequential enough to change a decision, experiment, or mental model.
- Distinct from the other selected ideas.
- Understandable without a visual appendix.

A famous source receives no automatic preference. A minor source can lead. A week with one strong idea should produce a short episode.

## Business-builder test

A technically impressive idea does not earn time unless it changes how the listener builds with AI. Each kept idea should answer four practical questions:

1. What did we learn?
2. What should the listener tell the AI agent to do differently?
3. What evidence should the listener request before accepting the work?
4. What result should trigger another iteration or a stop?

The default listener sets the outcome and constraints, then asks an AI agent to build and test. The episode should improve that direction-and-review loop. Technical mechanisms receive one short explanation when needed. Code, infrastructure, benchmark mechanics, architecture, and engineering process details should be removed when they do not change the listener's action.

## Claim discipline

The agents should keep four categories separate:

1. What a source directly observed.
2. How the source's author interpreted the observation.
3. What a vendor or institution claims about itself.
4. What the episode infers for the listener.

The spoken script should preserve this separation through attribution and careful transitions.

## Spoken structure

The narrator should not have to infer editorial structure from typography. Markdown headings, bullets, capitalization, and comma-heavy sentences may be obvious on a page but ambiguous in speech.

Major sections should be announced as plain spoken sentences:

```text
Section two. Why the evidence is weaker than the headline.
```

Subsections should use the same pattern:

```text
First point. The comparison group.
```

When several ideas belong together, announce the count and separate the items:

```text
There are three reasons this result needs another test.

First, the sample was small.

Second, the trial had no comparison group.

Third, the buildings differed before the intervention began.

Taken together, those limits make the result useful for designing a larger trial, not for forecasting citywide savings.
```

Each item is a complete sentence. The final transition sits in a new paragraph so the narrator cannot mistake it for another list item. Numbering should clarify a real sequence or set, not manufacture importance.

## The Critic's test

For the proposed episode, the Critic names:

- The strongest claim.
- The weakest joint.
- The missing evidence.
- The likely counterargument.
- The revision that makes the argument harder to dismiss.

If the editor cannot make those limits audible without overwhelming the idea, the material may belong in show notes rather than the episode.

## Attention test

After listening, record where attention dropped, where the host repeated a point, which caveat was hard to follow, and what action remained memorable. Revise the prompts from observed listening failures rather than adding generic production flourishes.
